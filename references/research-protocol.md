# 研究协议

## 证据获取

- `A`：已检查全文，并核验元数据。
- `B`：有可靠摘要和元数据。
- `C`：只有二手来源线索。

尽可能使用 `A`。如果只能使用 `B` 或 `C`，要说明证据降级、降低主张强度，并避免过度自信的谱系判断。

## 方向抽象：跨应用、分层机制

核心方向必须表示为 `研究对象 + 核心机制 + 目的`，但应优先保留跨模型、跨模态、跨任务仍成立的研究发现和机制。目标论文的模型、模态、任务、威胁场景、数据集、指标和实现算法不得自动进入核心方向。

先把论文内容分为四层：

1. **研究发现层**：论文发现了什么可迁移的现象、结构或规律？
2. **机制层**：什么内部操作、信息流、优化过程或因果关系解释该发现？
3. **实现层**：论文用什么算法、激活、损失、模块或阈值实现/验证该机制？
4. **应用层**：该机制被用于什么模型、模态、任务、攻击、防御、对齐或评测？

核心研究方向主要由前两层组成；第三层记录为“目标论文实例化”；第四层记录为“应用分支”。应用分支仍然可以进入谱系，但不能替代核心方向。

按以下证据链抽取核心机制：

1. 从核心主张中找出可跨应用检验的研究发现，并写成一句机制陈述。
2. 从方法、算法、架构或推理流程中描述该发现对应的可操作过程：输入/对象如何经过变换、交互、信息传递、优化或因果干预，形成什么中间状态并影响结果。
3. 执行抽象净化测试：暂时删除模型名称、模态、任务、攻击/防御场景、数据集、指标和具体算法。如果表述仍准确、可证伪并能解释贡献，则保留为核心方向；如果只剩宽泛主题，则回到机制证据。
4. 用消融、替换、剪枝、activation patching、探针、迁移或必要性实验检查该机制是否承担中心作用。证据优先级从强到弱为：必要性/消融/替换证据，有针对性的组件对照证据，方法中明确的主张与流程，摘要或二手来源线索。至少要有方法证据和实验证据；只有摘要时可提出机制假设，但必须标为“暂定”，并降低筛选强度。
5. 多个步骤并存时，选择直接支撑核心发现且可迁移的主机制；训练目标、实现组件和应用检测器另列为次要机制或应用分支。无法区分时，报告候选抽象和歧义，不得用具体应用场景替代。

使用下列格式保存方向抽象：

- `研究对象`：被操作、观测或解释的对象。
- `核心机制`：产生主要效果的操作/交互/信息流/优化或因果过程；应能回答“论文凭什么有效”。
- `核心机制说明`：用“输入/对象 → 关键操作 → 中间状态/信息流 → 目标效果”说明机制如何工作。
- `机制证据`：核心主张、方法描述、实验/消融证据及其出处。
- `主机制判定依据`：为何它比任务、目标、模型、数据集或其他模块更能代表论文的中心机制。
- `目的`：机制被用于解决的问题或实现的目标，只用于限定范围。
- `上位领域`：包含该方向的更宽泛研究领域。
- `同义词`：核心机制及其功能等价表达优先，其次才是对象和目的的术语。
- `范围`：核心机制适用的对象、输入和效果边界。
- `排除项`：仅共享对象、任务、目标、模型、数据集或评测指标，但没有机制对应关系的工作；以及仅基准测试、综述或纯应用变体。

核心机制自检问题：

- 若移除或替换该研究发现/内部机制，中心发现或解释是否失效或显著改变？
- 若只替换目标论文的模型、模态、任务或实现算法，核心方向是否仍成立？

若只有第二个问题的答案为“否”，所写内容通常是应用实现而不是核心方向。若没有实验支持机制判断，必须标为“暂定”或“含混”，并用“分析性推断”解释依据，不能只写未核验假设。

## 检索扩展

根据目标论文的核心发现/机制及其同义词建立第一优先级检索式，再分别用模型、模态、任务和应用词扩展应用分支；问题、任务、数据集和基线方法只作为补充。检索式应至少包含一组机制词，而不能只包含“领域 + 目标”这类主题词。从高相关论文出发，进行后向引用追踪和前向引用追踪。综述只能帮助发现候选论文，不能单独确立谱系事实。

### 发现—验证—利用三层谱系

对发现型机制至少分别寻找：

1. **最早直接证据**：最早显示该内部结构、稀疏性或信息流的论文。
2. **最早明确命名**：最早使用该机制术语或等价概念的论文。
3. **最早因果验证**：最早通过剪枝、消融、激活替换、patching、steering 或必要性实验验证作用的论文。
4. **最早应用利用**：最早将该发现用于检测、攻击、防御、对齐、编辑或评测的论文。

除非完成足够广泛的历史检索，不要把以上四种“首个”合并成一个未经限定的“首篇论文”。

## 筛选

按以下角色筛选论文：

- 起源
- 新证据
- 方法形成
- 泛化
- 工程化落地
- 攻击/防御
- 修正/挑战

先执行机制匹配，再执行谱系关系判断：

- **核心发现集合**：直接研究安全相关内部单元的稀疏性、定位、因果作用、迁移性或分布方式。
- **机制扩展集合**：研究与神经元功能等价或相近的 MLP 通道、注意力头、特征、rank、方向、子空间或安全回路，并明确说明对应关系。
- **应用利用集合**：利用稀疏安全机制进行运行时检测、选择性对齐、模型编辑、剪枝攻击、神经元恢复、跨模态迁移或自动化评测。

- `同一机制`：核心操作、关键作用和主要信息/因果流基本相同，即使对象、模型或实现不同。
- `相似机制`：实现形式不同，但承担相同功能，且保留与目标论文对应的关键中间作用或信息/因果流；必须写明对应关系。
- `仅主题相似`：只共享研究对象、任务、目标、数据集、模型或评测指标，没有可核验的机制对应关系；放入邻近工作。

相似机制必须记录：`目标机制功能 → 候选论文操作 → 保留的关键中间状态/信息流`。只有通过“同一机制”或“相似机制”门槛的论文，才可进入核心候选集、核心集合、核心时间线或发展谱系叙述；宽泛、综述、基准测试和证据薄弱的论文移至邻近工作，并说明理由。机制相似不等于引用继承，关系标签仍需遵守后续证据规则。

应用利用论文不能因为模型、模态或任务不同而被排除；但应用实现不能反向定义核心方向。报告中必须同时给出“核心发现/机制”和“应用分支”。

## 日期、版本与去重

使用最早可核验的公开版本排列时间线，单独记录正式发表信息。将同一工作的预印本、会议版、期刊版和修订版合并为一个时间线条目，并明确标出未解决的元数据冲突。报告前进行最终的单调时间顺序检查：将日期规范化为 `exact`（精确日期）、`month`（月份）、`unknown`（未知）或 `inferred`（推断），按最早可核验的公开日期排序并标出冲突。不得让后发表的论文在时间顺序相反的情况下挑战或修正更早的论文。`直接继承`、`延续`、`挑战` 和 `修正` 等关系标签必须同时符合时间方向和证据方向。

## 创新比较

对每篇核心论文记录：

- 继承基础
- 既有限制
- 新增量
- 关系类型

只有原始论文记录明确显示引用、动机、复用设置或延续说明时，才使用 `直接继承` 或 `延续`。如果关系只有机制相似性或概念检索支持，则使用 `候选前驱`、`机制类比`、`并行分支` 或 `分析性推断`，并说明引用关系尚未核验。英文关系术语仅用于维护者对照，不复制到最终报告。

### 稀疏性结论的可比性

当论文声称“少量”“稀疏”或给出安全相关比例时，必须记录：

- 内部单元定义：神经元、参数、通道、注意力头、rank、特征或子空间；
- 分母和计算范围：全模型、单层、单模块或被选层；
- 模型结构、数据条件和安全指标；
- 该比例是相关性、重要性、因果干预结果还是工程阈值。

不同单元定义和实验条件下的百分比不能直接合并成同一数量级结论。

## 饱和与报告

只有连续两轮都没有发现新的高相关核心论文时，才将检索视为已饱和。记录检索截止日期、使用的来源、检索式族、后向/前向追踪状态、筛选标准和局限性。最终报告中使用 `已饱和` 或 `未饱和`，不要只输出英文状态值。

## 降级模式

- 仅摘要：使用谨慎的主张摘要、较弱的支持标签，并明确说明不确定性。
- 没有已核验元数据的摘要不能直接标为 `B`；应使用 `B-degraded`（`abstract-only; metadata unavailable`），并说明缺失哪些元数据。
- 无法联网：只能依赖用户提供的文件和本地元数据，并说明无法在外部完成引用链追踪。
- 方向含混或机制证据不足：将机制判定状态明确标为“暂定”或“含混”，呈现候选抽象并用“分析性推断”解释歧义，避免过度删减候选论文；不得用宽泛主题填充核心机制。
- 没有有支持证据的前驱：报告“暂未找到有支持证据的前驱”，区分“缺少证据”和“证明不存在”，并保留邻近候选。
