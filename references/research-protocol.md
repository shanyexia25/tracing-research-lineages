# 研究协议

## 证据获取

- `A`：已检查全文，并核验元数据。
- `B`：有可靠摘要和元数据。
- `C`：只有二手来源线索。

尽可能使用 `A`。如果只能使用 `B` 或 `C`，要说明证据降级、降低主张强度，并避免过度自信的谱系判断。

## 方向抽象：机制优先

核心方向必须表示为 `研究对象 + 核心机制 + 目的`。它描述的是目标论文产生主要效果的可操作过程，而不是论文的宽泛主题、任务目标、数据集、模型名称或应用场景。即使论文主要解释、测量或刻画某个现象，也不能把现象直接放入核心机制位置；没有可识别机制时，应标为机制证据不足或含混，把现象记录在研究问题、范围或邻近方向中，并降低检索和筛选强度。

按以下证据链抽取核心机制：

1. 从核心主张中找出论文声称带来主要效果的步骤。
2. 从方法、算法、架构或推理流程中描述该步骤的可操作过程：输入/对象如何经过变换、交互、信息传递、优化或因果干预，形成什么中间状态并影响结果。
3. 用消融、替换、对照或必要性实验检查该过程是否承担中心作用。证据优先级从强到弱为：必要性/消融/替换证据，有针对性的组件对照证据，方法中明确的主张与流程，摘要或二手来源线索。至少要有方法证据和实验证据；只有摘要时可提出机制假设，但必须标为“暂定”，并降低筛选强度。
4. 多个步骤并存时，选择直接支撑中心贡献且证据最强的主机制；训练目标、实现组件和次要步骤另列为次要机制。无法区分时，报告候选机制和歧义，不得用宽泛主题替代。

使用下列格式保存方向抽象：

- `研究对象`：被操作、观测或解释的对象。
- `核心机制`：产生主要效果的操作/交互/信息流/优化或因果过程；应能回答“论文凭什么有效”。
- `核心机制说明`：用“输入/对象 → 关键操作 → 中间状态/信息流 → 目标效果”说明机制如何工作。
- `机制证据`：核心主张、方法描述、实验/消融证据及其出处。
- `主机制判定依据`：为何它比任务、目标、模型、数据集或其他模块更能代表论文的中心机制。
- `目的`：机制被用于解决的问题或实现的目标，只用于限定范围。
- `上位领域`：包含该方向的更宽泛研究领域。
- `同义词`：核心机制及其功能等价表达优先，其次才是对象和目的的术语。
- `范围`：核心机制适用的对象、输入和效果边界。
- `排除项`：仅共享对象、任务、目标、模型、数据集或评测指标，但没有机制对应关系的工作；以及仅基准测试、综述或纯应用变体。

核心机制自检问题：若移除或替换该机制，中心主张是否应失效或显著改变？若没有实验支持这个判断，必须把机制判定明确标为“暂定”或“含混”，并用“分析性推断”解释依据，不能只写未核验假设。

## 检索扩展

根据目标论文的核心机制及其同义词建立第一优先级检索式，再用研究对象和目的限制范围；问题、任务和基线方法只作为补充。检索式应至少包含一组机制词，而不能只包含“领域 + 目标”这类主题词。从高相关论文出发，进行后向引用追踪和前向引用追踪。综述只能帮助发现候选论文，不能单独确立谱系事实。

## 筛选

按以下角色筛选论文：

- 起源
- 新证据
- 方法形成
- 泛化
- 工程化落地
- 攻击/防御
- 修正/挑战

先执行机制匹配，再执行谱系关系判断：

- `同一机制`：核心操作、关键作用和主要信息/因果流基本相同，即使对象、模型或实现不同。
- `相似机制`：实现形式不同，但承担相同功能，且保留与目标论文对应的关键中间作用或信息/因果流；必须写明对应关系。
- `仅主题相似`：只共享研究对象、任务、目标、数据集、模型或评测指标，没有可核验的机制对应关系；放入邻近工作。

相似机制必须记录：`目标机制功能 → 候选论文操作 → 保留的关键中间状态/信息流`。只有通过“同一机制”或“相似机制”门槛的论文，才可进入核心候选集、核心集合、核心时间线或发展谱系叙述；宽泛、综述、基准测试和证据薄弱的论文移至邻近工作，并说明理由。机制相似不等于引用继承，关系标签仍需遵守后续证据规则。

## 日期、版本与去重

使用最早可核验的公开版本排列时间线，单独记录正式发表信息。将同一工作的预印本、会议版、期刊版和修订版合并为一个时间线条目，并明确标出未解决的元数据冲突。报告前进行最终的单调时间顺序检查：将日期规范化为 `exact`（精确日期）、`month`（月份）、`unknown`（未知）或 `inferred`（推断），按最早可核验的公开日期排序并标出冲突。不得让后发表的论文在时间顺序相反的情况下挑战或修正更早的论文。`直接继承`、`延续`、`挑战` 和 `修正` 等关系标签必须同时符合时间方向和证据方向。

## 创新比较

对每篇核心论文记录：

- 继承基础
- 既有限制
- 新增量
- 关系类型

只有原始论文记录明确显示引用、动机、复用设置或延续说明时，才使用 `直接继承` 或 `延续`。如果关系只有机制相似性或概念检索支持，则使用 `候选前驱`、`机制类比`、`并行分支` 或 `分析性推断`，并说明引用关系尚未核验。英文关系术语仅用于维护者对照，不复制到最终报告。

## 饱和与报告

只有连续两轮都没有发现新的高相关核心论文时，才将检索视为已饱和。记录检索截止日期、使用的来源、检索式族、后向/前向追踪状态、筛选标准和局限性。最终报告中使用 `已饱和` 或 `未饱和`，不要只输出英文状态值。

## 降级模式

- 仅摘要：使用谨慎的主张摘要、较弱的支持标签，并明确说明不确定性。
- 没有已核验元数据的摘要不能直接标为 `B`；应使用 `B-degraded`（`abstract-only; metadata unavailable`），并说明缺失哪些元数据。
- 无法联网：只能依赖用户提供的文件和本地元数据，并说明无法在外部完成引用链追踪。
- 方向含混或机制证据不足：将机制判定状态明确标为“暂定”或“含混”，呈现候选抽象并用“分析性推断”解释歧义，避免过度删减候选论文；不得用宽泛主题填充核心机制。
- 没有有支持证据的前驱：报告“暂未找到有支持证据的前驱”，区分“缺少证据”和“证明不存在”，并保留邻近候选。
